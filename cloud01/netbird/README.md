# NetBird server (cloud01)

The NetBird control plane (management, signal, relay, STUN, embedded IdP and
dashboard) runs as its own compose project in `/srv/netbird`, generated by
NetBird's official quickstart. It isn't checked in: the generated files include
`config.yaml`, which holds the key that encrypts NetBird's database.

## Install

```bash
sudo install -d -o "$USER" -g "$USER" -m 0750 /srv/netbird
cd /srv/netbird
curl -fsSL -o getting-started.sh https://github.com/netbirdio/netbird/releases/latest/download/getting-started.sh
less getting-started.sh          # read it before running it
export NETBIRD_DOMAIN=nb.cloud.example.com
bash getting-started.sh
```

| Prompt | Answer |
|---|---|
| Reverse proxy | `1` — existing Traefik |
| External network | `stack_default` |
| HTTPS entrypoint | `websecure` |
| Cert resolver | `cloudflare` |
| NetBird Proxy service | No |
| CrowdSec | No (CrowdSec already runs in the main stack) |

## Edits after the installer

1. Prepend `crowdsec@file,` to every router's `middlewares` label in the
   generated `docker-compose.yml` (add a middlewares label if a router has none).
2. Add `com.centurylinklabs.watchtower.enable=true` to both services so the
   control plane updates nightly with everything else.
3. `docker compose up -d`.

## Identity

- First account created on the setup page is a local break-glass admin.
- Google added under **Settings → Identity Providers**. The OAuth consent
  screen stays in *Testing*; its **Test users** list is the allow-list.
- 2-Step Verification is required on every allowed Google account.

Groups and policies: [`docs/netbird-policies.md`](../../docs/netbird-policies.md).
